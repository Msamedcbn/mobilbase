## Fixed Issues

### #30 CRITICAL — SyntaxError in local-store.ts (lib/local-store.ts:513)

**Root cause:** Empty character class regex `/\[]/` is a SyntaxError per ECMAScript spec. The entire `local-store.ts` module would fail to load, crashing every API route and page that imports it (checkout, portal, webhook, pricing, customers, etc.).

**Fix:** Changed to `/[ÃÂÄÅ]/u` which matches common double-encoded UTF-8 corruption patterns that the `maybeFix` function was designed to repair. Also added a Unicode flag for correctness.

**Before:** Would crash at module evaluation time with `SyntaxError: Invalid regular expression: /[]/: empty character class`.  
**After:** Module loads correctly, UTF-8 repair logic functional.

---

### #23 HIGH — Webhook race condition (lib/local-store.ts:590)

**Root cause:** File-based JSON store used read-modify-write without any concurrency control. Simultaneous webhooks (e.g. `subscription_created` + `subscription_payment_success`) could read stale data, causing lost subscription state updates.

**Fix:** Added in-memory mutex (`acquireLock()`) to serialize writes within the same Node.js process. Also switched to atomic write (write to `.tmp`, then `fs.rename`) to prevent partial/corrupt files if the process crashes mid-write.

**Before:** Last-write-wins race on `local-store.json`.  
**After:** Serialized writes within same process, atomic file swap.

---

### #1 MEDIUM — Feature property loss on pricing edit (app/studio/pricing/page.tsx:375)

**Root cause:** `{ ...editPricing.features[plan], supportLevel: "..." }` — if `editPricing.features[plan]` was undefined (possible in edge states during edit mode), spreading would produce an object with only `supportLevel`, dropping `pos`, `repairs`, `stock`, `invoicing`, `buyback`.

**Fix:** Added default fallback: `{ ...(editPricing.features[plan] || { pos: false, ... }), supportLevel: "..." }`. Same fix applied to the feature toggle at line 342.

**Before:** Editing a plan's support level could silently wipe all module feature flags.  
**After:** Defaults preserve all six feature properties.

---

### #21 MEDIUM — Missing auth on portal route (app/api/subscriptions/portal/route.ts)

**Root cause:** `GET /api/subscriptions/portal` had no `requireRole()` check. Any authenticated user could enumerate tenant IDs and access their LS billing portal URLs.

**Fix:** Added `requireRole(["ADMIN", "PLATFORM_OWNER", "MANAGER", "CASHIER", "TECHNICIAN", "ACCOUNTANT"])` at the top of the handler.

**Before:** Missing authorization guard.  
**After:** Auth enforced, matching the checkout route's policy.

---

### #10 MEDIUM — Hardcoded annual discount badge (app/ayarlar/abonelik/page.tsx:475)

**Root cause:** The "−15%" badge was a hardcoded string, ignoring the configurable `addons.annualDiscountPct` from the pricing system.

**Fix:** Exported `ANNUAL_DISCOUNT_PCT` constant from `lib/subscription-plans.ts` and used `{ANNUAL_DISCOUNT_PCT}%` in the badge. This at minimum centralizes the default; a future improvement would fetch pricing from the API.

**Before:** Discount badge always showed "−15%", even when studio admin changed it.  
**After:** Uses shared constant, one source of truth for the default.
